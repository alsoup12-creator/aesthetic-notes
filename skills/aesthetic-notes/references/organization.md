# Agent 整理结果

先 `show 编号 --json` 阅读完整记录，并查看实际原件。记录 `revision`，再提交下面的 JSON；字段均由 Agent 填写，不交给用户填表。

```json
{
  "title": "简洁、可识别的材料名称",
  "facets": ["视觉"],
  "tags": ["阅读", "文字层级"],
  "summary": "原件与标注的简要内容；不把描述冒充用户偏好。",
  "observations": "有依据的形式、内容或交互观察。只阅读了哪些页或附件也在这里说明。",
  "preferenceInterpretation": "对用户偏好的推测及适用条件。没有足够标注时保留不确定性。",
  "evidence": "使用的原始附件名、页码/区域、用户标注原话或说明文件中的原句，并区分材料描述与用户意见。",
  "relevantTasks": ["中文长文阅读界面"]
}
```

`title`、`facets`、`tags` 为必填结构，后两者可为空数组；其他字段可留空。facet 可用“视觉”“文字”“产品”，一条记录可多选；不适合既有分类时可用更合适的类别。不要无依据补写作者、出处、交互效果或用户意图。

文件夹中的多个附件不必强行合成同一种风格。可在观察和依据中分别注明局部参考、材料之间已确认或尚不明确的关系。

网页和交互笔记在 `observations` 与 `evidence` 中注明实际查阅方式：仅读代码、本地预览实际操作、原站实际操作，或录屏观察。网页注明 URL 与操作路径；录屏注明有关时间段。材料已收录不等于交互已验证，静态代码或截图也不能证明原站后台行为。缺失资源、不可用接口及未查看的部分应明确保留。

保存命令只接受读取时的当前版本，写入 `organization` 字段；原文件夹与用户标注不会因此修改。网页会显示 Agent 整理结果，材料变化后显示待更新。

独立整理不需要一个当前创作任务。`relevantTasks` 可以填写从材料中有依据推导的适用场景；暂时无法判断时留空。跨笔记形成的理解，应在 `evidence` 中列出其他笔记编号及对应原件或标注，区分重复出现的材料特征与用户已明确表达的偏好。
